# 결정 완료 (2026-11-12)

`docs/decision/1~4.md`의 결정 대기 항목과, 이전 리뷰에서 "미루기로 함"으로 남겨 둔 항목에 대한 사람의 결정이다.

**리뷰어·수정자에게:**
- 아래 항목은 더 이상 "결정 대기"가 아니다.
- "구현"으로 표시된 항목이 코드에 반영되지 않았으면 리뷰에서 이슈로 올린다. 이슈 제목에 결정 번호를 붙인다 (예: `[D2-1 구현]`).
- 수정 단계에서는 결정 내용대로 구현한다.
- "하지 않음"·"현행 유지"로 표시된 항목은 다시 지적하지 않는다.

## 전제

- **서비스 중인 프로젝트가 아니다.** 과거 데이터·백업·원고 형식과의 호환은 고려하지 않는다. 마이그레이션 코드는 만들지 않는다. 값이 충돌하면 최신 값을 우선한다.
- **Vercel에 배포할 예정이다.** `next.config.ts`의 `headers()`가 실제로 적용된다.

## 저장소·백업

### D2-1 백업 합치기 규칙 → 구현: 최신 우선으로 통일
- 각 저장소에서 더 최근 값이 이긴다.
  - seen: 본 날짜가 더 최근인 값
  - log: `ts`가 더 최근인 값 (같은 `id|date` 기준)
  - srs: 마지막 복습 시각이 더 최근인 값
- 번역 캐시(kocache)에는 시각 정보가 없으므로 현행 "기존 값 우선"을 유지한다.
- 같은 시각이면 기존 값이 이긴다.
- 백업 카드에 규칙 한 줄을 추가한다: "합치기는 더 최근 기록을 남깁니다. 백업 내용 그대로 되돌리려면 '기존 기록을 지우고 대체'를 사용하세요."
- 네 `import*` 함수 각각에 "누가 이기나" 테스트를 추가한다.

### D3-1 두 탭 동시 사용 → 구현: 다른 탭 경고만
- `BroadcastChannel`로 같은 앱이 다른 탭에서 열려 있음을 감지하고 배너로 알린다.
  - 예: "다른 탭에서도 열려 있습니다. 한 탭에서만 사용하세요 — 동시에 쓰면 기록이 덮어써질 수 있습니다."
- 저장 형식은 바꾸지 않는다. 버전 락과 병합은 하지 않는다.

### D4-2 저장소 상한 → 구현: 연습 기록 상한 상향 + 잘린 개수 알림
- **상한 상향:** `MAX_RECORDS`(현재 400, `src/lib/practice.ts:29`)를 올린다.
  - 기록 1건의 평균 직렬화 크기를 실측한다.
  - localStorage 한도(약 5MB) 안에서 다른 저장소(seen, kocache, srs)와 합쳐도 여유가 있는 값으로 정한다.
  - 근거 수치를 주석에 남긴다.
- **잘린 개수 알림:** `importLog`·`importSrs`·`importSeen`·`importKoreanCache`가 `{ stored, rejected, trimmed }` 같은 결과 객체를 돌려주게 바꾼다.
  - 백업 복원 결과 문구에 "N건은 상한으로 제외" 등을 표시한다.
  - 리뷰 5-7(대체 복원의 중복 쓰기·부분 적용)도 이 결과 객체 흐름 안에서 정리한다.

### D1-1 파괴적 초기화 → 구현: 모든 삭제 버튼에 확인
- 전체 초기화, 연습 기록 + 복습 큐 삭제, 부분 삭제 버튼("동화 기록 지우기", "한국어 번역 캐시 지우기" 등) 모두 `window.confirm`을 받는다.
- 문구: "되돌릴 수 없습니다 — 먼저 백업을 내보내세요".

### D1-2 큰 저장소 쓰기 비용 → 현행 유지
- 코퍼스 전체가 약 4,400문장이라 seen 상한(2만 건)에 닿기 어렵다. 다시 지적하지 않는다.

### entryKey 32비트 해시 → 구현: 64비트로
- 충돌 확률을 사실상 0으로 만든다.
- 키가 바뀌어 브라우저의 기존 seen·번역 캐시가 무효가 되는 것은 받아들인다. 마이그레이션은 하지 않는다.
- 코퍼스 빌드의 번역 캐시는 `normalizeKey(en)`를 쓰므로 영향이 없다.

## 코퍼스·번역 도구

### D4-1 코퍼스 덮어쓰기 가드 → 현행 유지
- 결정 문서의 전제가 틀렸다. `public/data/corpus/classics.json`은 git에 커밋돼 있다.
- 덮어써도 `git diff`로 보이고 `git checkout`으로 복구된다. 가드를 강화하지 않는다.
- 리뷰 5-1(새로 내려받은 잘린 원본을 검사하지 않음)은 별개의 버그이므로 수정 대상이다.

### D4-3 외국어 허용 목록 → 구현: 공용 목록 하나
- `scripts/lib/`에 기준 허용 목록을 둔다.
- check, audit, `corpus-data.test.mts`가 모두 그 목록을 읽는다.
- `--allow=`는 기준 목록에 더하는 용도로 check와 audit 둘 다에 남긴다.
- 목록 항목마다 허용 근거를 주석으로 단다.

### D3-2 번역 원고 검증 → 구현: 원고에 원문 대조
- 원고 형식을 `번호\t원문 앞부분\t번역`으로 바꾼다.
- `dump-untranslated.mts`가 이 형식의 빈 원고 틀을 내보낸다.
- `merge-translations.mts`는 원문 앞부분이 worklist의 `en`과 맞지 않는 줄이 있으면 거부한다.
- 예전 형식(번호\t번역)과의 호환은 두지 않는다.

### D2-2 과거 파서 결함 데이터 → 종결 (오염 없음)
- 근거 1: `classics.json`의 한국어 1,400문장은 모두 커밋 `2e62963`에서 사람 원고로 채워졌다. 그 전에는 0건이었다. LLM 배치 파서(R2-1)를 거치지 않았다.
- 근거 2: 영어·한국어 길이 상관으로 줄이 밀렸는지 검사했다. 14권 모두 제자리 상관(0.77~0.86)이 한 칸 어긋났을 때(0.50~0.65)보다 뚜렷이 높아 밀린 곳이 없다.
- 번역 품질 문제(사투리 직역, "Rat"→"생쥐", "March Hare"→"봄토끼" 등)는 별개 과제이며 이 루프의 범위가 아니다.

### hasVerb 필터 → 구현: 잡음 필터만 추가하고 코퍼스 재생성
- `hasVerb`(`src/lib/corpus-tools.ts:199-207`)는 난이도 판정이 아니라 문장 수록 필터다.
  - `-s` 규칙만으로 통과한 74문장 대부분이 정상 문장이다.
  - 따라서 **`-s` 규칙은 그대로 둔다.**
- 대신 다음 잡음만 따로 거른다.
  - 문장 중간에 `Chapter` + 로마숫자가 있는 제목 패턴 (예: "Glinda The Good Witch Grants Dorothy's Wish Chapter XXIV.", "The Garden of Live Flowers CHAPTER III.")
  - 비영어(라틴어 등) 문장 (예: "Duplex libelli dos est…")
- 코퍼스를 재생성한 뒤 `git diff public/data/corpus/classics.json`으로 확인한다.
  - 빠진 문장은 잡음 몇 개뿐이어야 한다.
  - 기존 사람 번역은 유지돼야 한다.
- 새로 들어온 문장은 `ko`가 비어 있게 된다. 이 문장은 D3-2의 새 원고 형식으로 사람이 번역한다.

### pickHints seed → 구현: 쓰지 않는 코드 제거
- 유일한 호출부가 항상 0을 넘긴다. seed 인자와 번갈아 보여주기 로직을 지운다.
- 만들어지는 힌트는 그대로다.

### 데이터 개수 하드코딩 테스트 → 현행 유지
- `corpus-data.test.mts`의 3,000 / 1,400은 빌드 상한과 짝을 이루는 의도된 잠금장치다.

## 개발 도구·보안

### 커버리지 → 구현: devDependency로 설치
- `@vitest/coverage-v8`을 devDependency로 설치하고 `npm run coverage` 스크립트를 추가한다.
- 기준 미달 시 실패하는 강제 조건은 두지 않는다.
- 이후 리뷰는 `/tmp` 사본을 만들지 말고 이 스크립트로 측정한다.

### npm audit → 구현: fix + CI 게이트
- `npm audit fix`로 개발 의존성 moderate 7건을 정리한다. 정리 후 테스트·빌드·린트가 통과해야 한다.
- CI(`.github/workflows/ci.yml`)에 `npm audit --omit=dev`를 추가한다.

### CSP → 구현: 정적 CSP (nonce 없음)
- `next.config.ts`의 `headers()`에 추가한다. 페이지의 정적 생성은 유지한다.
- 기준값:
  ```
  default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
  img-src 'self' data:; font-src 'self'; connect-src 'self' https: http://localhost:* http://127.0.0.1:*;
  object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
  ```
- `connect-src`는 사용자가 설정하는 LLM 주소(로컬 포함)로 브라우저가 직접 요청하므로 넓게 연다.
- 개발 서버에서 깨지면(`'unsafe-eval'` 필요 등) 개발 모드에서만 완화한다.
- 빌드 후 실제 화면에서 LLM 호출·폰트·스타일이 막히지 않는지 확인한다.

### 하지 않기로 함 (다시 지적하지 않음)
- 번역 도구 전 과정 CI 게이트 (check → merge → audit를 샘플 데이터로 돌리는 작업)
- `packageManager` 필드, GitHub Actions SHA 고정
