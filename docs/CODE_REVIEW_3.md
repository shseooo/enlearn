## 1. 배경과 위험

코퍼스빌더는 원래 `--llm`으로 동화 문장의 한국어를 채운다. 이번에는 LLM 접속 정보 없이 1,400문장을 옮겼기 때문에, **번역 캐시(`.corpus-cache/translations.json`)가 원본 자료**가 됐다. 그래서 위험은 네 가지로 정리된다.

1. **행 어긋남** — 순서가 한 줄만 밀리면 모든 번역이 다른 문장에 붙고, 그 상태가 코퍼스에 영구로 남는다.
2. **언어 혼입** — 한국어 문장에 라틴·일본 가나·중일한자·키릴·태국·베트남 문자가 섞인다(이 세션에서 실제로 20회 이상 발생).
3. **자료 유실** — 캐시는 JSON 한 장이다. 쓰는 도중에 멈추면 1,400개가 한 번에 사라진다.
4. **판정의 근거가 흔들림** — 검사 도구가 여러 곳에 복사되면, 한 곳은 통과하고 다른 곳은 실패하는 애매한 상태가 생긴다.

아래 항목은 이 네 가지 위험을 기준으로 코드를 읽고 재현해 발견한 것이다.

## 2. 발견 항목과 처리

| 번호 | 우선순위 | 내용 | 판단 | 조치 |
| --- | --- | --- | --- | --- |
| R3-1 | 높음 | 번역 캐시를 `writeFileSync`로 바로 덮어써서, 쓰기 도중에 프로세스가 죽으면 캐시 전체가 부서진다. 빌더는 부서진 캐시를 **조용히 빈 캐시로 취급**하므로 1,400개가 사라진다 | 타당 | 임시 파일에 쓰고 `renameSync`로 교체하는 원자적 쓰기로 변경 |

| R3-5 | 중간 | 외국어 문자 조각이 숫자에서 잘린다. 허용 목록에 `C`가 있으면 `C20`까지 통과한다(허용 범위가 부분 일치로 커지는 구멍) | 타당(직접 재현) | 외국어 문자로 시작된 조각에 이어지는 숫자를 같은 조각으로 본다. 테스트로 고정 |
| R3-6 | 높음 | `worklist.tsv` 첫 열은 `classics.json` 배열 번호였는데, `merge`는 그 번호를 **작업 목록 순서**와 비교했다. 이미 번역된 문장이 섞이면(배열 번호가 밀리면) 모든 줄이 거부되거나 엉뚱하게 대응한다. 지금은 1,400개 전부 비어 있어 우연히 일치했을 뿐 | 타당 | 작업 목록을 3열로 분리: `<작업 행 번호>\t<코퍼스 배열 번호>\t<원문>`. 원고에 적는 번호는 작업 행 번호. `merge`는 작업 목록 자체의 번호·순서 손상도 검증. 임시 코퍼스로 재현·고정(`translation-workflow.test.mts`) |

## 4. 처리하지 않은 항목과 이유

| 항목 | 판단 | 이유 |
| --- | --- | --- |
| 번역 원고(`.corpus-cache/ko/*.txt`)를 커밋하지 않는 것 | 인정(의도) | `.corpus-cache/`는 gitignore 대상이고, 원고는 중간 산출물이다. 근거는 결과물(코퍼스 JSON)과 재현 절차(README)로 남긴다 |
| `merge`가 언어가 섞인 줄도 합치는 것(경고만) | 인정 | 허용해야 할 표기(TV, DNA, 고유명사)가 원고마다 다르다. 실패로 막으면 정상 원고까지 막는다. 최종 게이트는 `audit`(언어 오염 시 종료 코드 1)과 `corpus-data` 테스트로 둔다 |
| `daily.json` 한국어에 `Tom`, `Mary` 같은 라틴 문자가 남는 것 | 인정-허용 | Tatoeba가 제공한 번역 원문이다. 검사 예외 목록(`ALLOWED_LATIN`)에 어디까지 허용하는지 명시했다. 동화 레인에서는 예외가 쓰이지 않는다 |
| `corpus-data.test.mts`가 개수(3,000 / 1,400)를 하드코딩하는 것 | 인정 | 의도된 잠금장치다. `build-corpus.mts`의 `DAILY_CAP` / `CLASSIC_CAP`과 짝을 이루며, 한도를 바꾸면 함께 고치라는 주석을 뒀다 |
| `classics.json`이 327KB → 441KB로 는 것 | 인정 | 사전 번역의 대가다. 동화 레인에서 런타임 LLM 번역이 사라지는 대신 파일이 커졌다. README에 크기와 압축 안내를 넣었다 |
| 원고 청크 크기를 100줄로 정한 것 | 인정 | 검사·병합 거부 메시지가 줄 번호로 나오므로 100줄이 사람 검토에 맞는 단위였다. 코드에 하드코딩하지 않았다 |

## 5. 잔여 과제 (이번 범위 밖)

- 사전 번역 도구사슬에 대한 CI 게이트는 없다. `audit`는 사람이 돌리고, 커밋된 데이터만 테스트로 검사한다. 원고를 다시 합치는 흐름 전체를 CI로 돌리려면 fixture를 만든 뒤 3개 스크립트를 순서대로 실행하는 잡이 필요하다.
- 동화 레인 힌트는 어휘 빈도 기반이다. 한국어가 미리 채워진 지금도 힌트 품질은 원문 기준이므로, 학습자 수준별 힌트 조정은 별도 과제다.
- `classics.json`의 고어체 문체에 대한 난이도 산정(백분위)은 이번 번역과 무관하게 그대로다.
