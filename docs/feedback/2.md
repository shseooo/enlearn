### R2-1 배치 파서의 0-based 어긋남 — 수정
- 변경 파일: `src/lib/parse-batch.ts:32-40,77-118`, `scripts/build-corpus.mts:573-577`(폐기 사유 로그), 테스트 `src/lib/__tests__/parse-batch.test.ts:31-88`
- 검증: 지적 맞음. 지적된 줄(`parse-batch.ts:92`)의 `index = n >= 1 && n <= expected.length ? n - 1 : n`은 항목마다 기준을 판정한다. 리뷰의 재현 커맨드를 그대로 실행해 `Beta sentence two. => 감마 문장입니다.`를 확인했다.
- 어떻게 수정했는지:
  - 항목마다 정하던 판정을 없애고, 번호 집합을 먼저 모은 뒤 **배치 전체에 대해 기준을 한 번** 정한다: `0`이 없으면 1-based(기본), `0`이 있고 `0..n-1` 범위 밖 번호가 있으면 0-based, **`0`과 `n` 이상 번호가 함께 오면 기준이 섞였으므로 번호 대응을 통째로 버린다**(`numberBase = null`).
  - 기준이 무너진 배치는 `onReject` 콜백으로 사유를 남긴다 → `translateBatch`가 `! 응답 번호 대응 폐기: …`로 출력(조용히 넘어가지 않는다).
  - 기준 폐기 후에도 항목에 명시된 `en`/`sentence` 원문 대조는 그대로 살린다(추측이 아니라 정확한 식별자이므로). 자릿수 추측은 여전히 금지.
- 검증: 리뷰 재현 커맨드 재실행 → 세 문장에 각각 올바른 번역, 혼합(`i:0` + `i:3`) → 0건. 회귀 테스트 2개 추가 — ① 0-based 3항목 + 일부만 답한 0-based 목록이 제자리에 붙는지, ② 기준 혼합 시 0건 + 폐기 사유 1건. 기존 1-based·`en` 대조·순서 약속 테스트는 그대로 통과.

### R2-5 백업 병합 우선순위가 네개 `import*`에서 서로 반대 — 보류(결정 필요)
- 검증: 지적 맞음. `corpus.ts`의 `importSeen` merge `{ ...loadSeen(), ...incoming }`(들어온 값 우선)와 `importKoreanCache` merge `{ ...incoming, ...exportKoreanCache() }`(기존 우선)가 인접해 있으면서 반대이고, `importLog`는 같은 id·날짜에서 새 값 우선, `importSrs`는 진척 우선이다. `MAX_SEEN` 트림이 seen 값(날짜) 순서로 오래된 것을 버리므로, 옛 백업 병합이 최근 seen을 밀어낼 수 있다.

- 이번 사이클에서 하지 않은 것: 현행(서로 다른) 규칙을 테스트로 고정하지 않았다. 결정 후에 클리핑 규칙과 함께 테스트를 추가해야 한다.

### R2-15 `exportKoreanCache`의 미검증 값에 검증된 타입 — 수정
- 변경 파일: `src/lib/corpus.ts:504-516`, `src/lib/storage.ts:79-80`(freeze 주석), 테스트 `src/lib/__tests__/corpus.test.ts:230-249`
- 검증: 지적 맞음. `exportKoreanCache`는 `readJson<Record<string, CachedKorean>>`(평면 객체 검사만) 결과를 그대로 반환하고 있었고, `parseStored`의 `Object.freeze`는 최상위만 얼린다.
- 어떻게 수정했는지: 내보내기 시점에 기존 클리퍼 `normalizeCachedKorean`을 항목별로 통과시켜, 통과한 항목만 새 객체에 담는다. `hints: [42]`는 `hints: []`로 시정되고, `ko: 42` 같은 항목은 빠진다 → "내보낸 백업은 검증된 타입"이라는 선언이 사실이 된다. 얕은 freeze는 주석을 "최상위 층만"으로 바로잡아 그대로 둔다(값 복사 규칙 유지).
- 검증: 손상된 캐시를 `localStorage`에 직접 심어 내보내기 결과를 단언하는 테스트 추가 — 남은 키는 `{classic:ok, classic:bad-hints}`뿐이고 모든 값이 `CachedKorean` 모양이다. `backup.test.ts`의 왕복 테스트는 그대로 통과.
