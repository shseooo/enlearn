### R4-5 [경미] [버그] `isCorpusEntry`가 null을 허용하는 필드의 "키 누락"을 형식 오류로 처리한다
- 위치: `src/lib/corpus.ts:65`(`e.ko !== null && typeof e.ko !== "string"`), `src/lib/corpus.ts:67`(`e.sourceId !== null && typeof e.sourceId !== "string"`)
- 문제: 타입은 `ko: string | null`, `sourceId: string | null`이다. 그런데 검사식 기준으로 키가 아예 없으면(`undefined`) `undefined !== null`이 참이 되어 즉시 거부된다. 즉 `null`은 되고 키 누락은 안 된다. 커밋된 두 파일은 전 항목에 키가 있어 지금은 증상이 없지만(`daily.json` 3,000 / `classics.json` 1,400 전부 `ko`·`sourceId` 보유), 코퍼스 JSON을 손으로 편집하거나 생성기가 `sourceId` 생략 방식으로 바뀌면 **파일 전체가** "코퍼스 파일 형식이 올바르지 않습니다"로 거부돼 해당 레인이 전혀 학습되지 않는다.
- 근거: 사본에서 `loadCorpus`로 확인했다 — `lane/en/hints/difficulty/source`가 모두 올바른 항목 하나에서 `ko`·`sourceId` 키만 뺀 파일 → `코퍼스 파일 형식이 올바르지 않습니다 (/data/corpus/classics.json)`, 같은 항목에 `ko: null, sourceId: null`을 넣으면 통과. `!== null &&` 패턴은 리포지토리에 이 두 곳뿐이다(`grep -rn "!== null && typeof" src scripts`) — 의도가 "선택적 null 허용"임이 분명하다.
- 제안: `e.ko != null && typeof e.ko !== "string"`(sourceId도 동일)로 바꿔 `undefined`와 `null`을 같은 취급으로 만든다. R4-9의 통과 경로 테스트와 같이 넣으면 규칙이 고정된다.
