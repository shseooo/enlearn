    ...
  }
  ...

- 문제: `clearKoreanCache()`(`:250`)는 직렬화+쓰기이고, 같은 배치 안에서 바로 뒤의 `importKoreanCache(file.data.koreanCache, replace=true)`(`:256`)가 같은 키를 **무조건 덮어쓴다**(replace 경로는 병합 없이 `trimKoreanCache(incoming)`를 그대로 쓴다 — `src/lib/corpus.ts:599-601`). replace 모드에서 이 미리 지우기는 완전히 중복이다. 그리고 `importLog`/`importSrs` 쓰기가 용량 때문에 실패하면(`writeFailed`), 캐시 지우기는 이미 끝나 있어 **되돌려지지 않는다** — log는 그대로이고 캐시만 비는 중간 상태가 남는다.
- 근거:
  ```ts
  if (replace) {
    // import*(replace=true)가 빈 목록으로도 저장소를 비운다
    clearKoreanCache();                    // ← 쓰기 #1 — 아래가 어쨌든 같은 키를 덮어쓴다
  }
  return {
    log: importLog(file.data.log, replace),          // 여기서 실패해도 캐시 지우기는 취소되지 않음
    ...
    koreanCache: importKoreanCache(file.data.koreanCache, replace),  // ← 쓰기 #2 (같은 키)
  ```
- 제안: replace 경로에서 `clearKoreanCache()`를 빼면 중복 쓰기가 사라지고, 남은 문제(부분 적용)는 D4-2/D3-1의 "쓰기 실패를 한 개의 결과로 모은다"는 흐름 안에서 함께 다루면 된다(예: 모든 `safeSetItem`이 성공할 때만 커밋하도록 마지막에 한 번 쓰거나, 실패 시 이전 값을 되돌리기). 최소한 지금의 중복 쓰기 하나는 제거한다.
